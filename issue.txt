  What We've Discovered

  1. Audio keeps pulsing in 1-second pattern (1 sec sound, 1 sec silent) = scheduler is running but video is frozen
  2. The freeze is NOT caused by:
    - ProcUIProcessMessages (we fixed it to skip when already in foreground)
    - gfx_wiiu_start_frame GPU wait loop (we tested removing it)
    - Graphics initialization (we tested various approaches)
    - Graphics startup code
  3. The freeze IS caused by:
    - Something in menu rendering code specifically
    - The 1-second audio pulse pattern suggests a periodic timeout or retry loop
    - Hardware-specific (CEMU doesn't have the issue)

  The Real Problem

  The menu rendering code has a hardware-specific issue that causes:
  1. Scheduler to be unable to progress video rendering
  2. Audio to continue in 1-second pulses (suggests periodic timeout/retry)
  3. Never actually crashes - just stays frozen indefinitely

  The 1-second pulse pattern is very specific and suggests either:
  - A timeout loop in menu code
  - A resource exhaustion that recovers every ~1 second
  - A periodic retry mechanism
